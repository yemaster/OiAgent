## 任务模板

在新建任务输入框旁打开「任务模板」。模板可以分类、搜索、预览、编辑，也可以将当前输入保存为新模板。

模板中的 `{{变量名}}` 会生成填写项。例如：

```text
检查 {{模块}} 的错误处理，重点关注 {{场景}}。
先说明发现的问题，再修改代码并运行相关测试。
```

插入时默认追加到已有内容，选择替换才会覆盖。模板保存在本机的 `task-templates.json`。

## Prompt 优化

点击输入框旁的魔法棒，选择更清晰、更精简或结构化。此功能需要先配置 [LLM API](../api/)。

只发送当前输入文本，不读取项目文件、不启动 Agent。建议可以继续编辑，确认后替换原文，紧接着可以撤销。等待期间修改了原文，需要重新优化。

## 工作流

从左侧「自动化」进入，工作流与运行记录分开显示。工作流可以保存、复制和重复运行，删除工作流不会删除已有运行记录。

### 创建与启动

1. 点击「新建工作流」，或选择「并行审查 → 汇总」「检查 → 条件分支 → 汇总」等示例。
2. 填写名称、任务目标与项目目录。目录留空时，启动会创建临时项目。
3. 在右侧「工作流」设置中选择**默认 Agent**。新增 Agent 节点沿用此选项，需要例外时在节点设置中单独选择。
4. 通过「添加节点」菜单选择类型，从右侧出口拖到下一节点的左侧入口建立连接。点击节点编辑内容，点击连线可删除；「整理布局」重新排列节点。
5. 保存以便复用，或点击「启动」按当前内容创建一次独立运行。

画布占据编辑区域，保存和启动按钮固定在顶部，生成计划与 LLM API 设置位于任务目标下方。右侧设置分为「工作流」和「节点」；节点下的「内容 / 执行 / 连接」分别编辑 Prompt、Agent 参数及连线。设置面板可以收起，切换分类不会重置画布或草稿。

也可以在「节点 → 连接」中用下拉选项连线。移动节点只改变位置，执行关系由连线决定。删除节点会同时删除相连的线，不会自动接通前后节点。

「生成计划」使用已配置的 [LLM API](../api/) 将目标转为可编辑的图，保留所选默认 Agent。生成时发送目标及可用 Agent 名称、标识和类型，不读取项目文件。返回的计划默认不覆盖模型和 API，不开启自动返工或执行时限；检查并点击启动后才会执行。

### 节点类型

| 类型 | 配置与行为 |
| --- | --- |
| Agent 任务 | 沿用默认 Agent，或单独选择已安装的程序。每个节点可设置权限、模型、Claude Code API 和执行时限。 |
| 人工确认 | 该路径等待用户确认，独立路径继续执行。在运行图中选中节点，可填写补充说明、确认继续或停止整个工作流。 |
| LLM 检查 | 对照前置结果检查验收标准。不通过时等待处理，也可以配置有限次数的返工。 |
| 条件分支 | 填写一个能回答“是 / 否”的问题。LLM 根据前置结果选择对应出口；两个出口都需要连接。证据不足或响应格式错误时等待处理，不猜测路径。 |

LLM 检查和条件分支会收到前序报告，以及其中引用的文本文件正文。它们不能自行查找更多文件或执行测试；实际检查仍由 Agent 完成，再将结果连接到判断节点。仅包含 Agent 和人工确认的工作流不需要额外配置 LLM API。

### 并行、分支与汇合

没有前置连线的节点是起点。同一节点可以连接多个后续节点，也可以将多条路径连接到同一节点。

- **并行**：独立的只读 Agent 任务可以同时运行，最多并行数可设置为 1–4，默认 2。
- **写入**：节点共享项目目录。同一工作流中，允许修改项目的 Agent 不会与其他 Agent 同时执行。该限制不替代 Agent 自身的权限控制，也不隔离其他工作流或手动任务。
- **分支**：条件节点只启用选中的出口，另一条路径标记为「已跳过」。
- **汇合**：等待所有前置节点完成或跳过，至少一条连线有效才执行；所有输入路径均被跳过时，汇合节点也跳过。前置节点失败或等待确认时，依赖它的节点不会启动。

Agent 收到任务目标、已完成的上游结果摘要、引用文件的节选及用户补充，不会收到未连接路径的结果。完整执行记录保留在子任务中。文件节选有长度上限，Agent 可在已有权限内继续读取。

图中不允许循环连线。需要反复修改与验证时，使用检查节点的有限返工功能。

### 检查与返工

检查节点只有一个前置 Agent，且该 Agent 没有连接其他节点时，可以启用自动返工，最多 1 次或 2 次。Agent 收到检查意见，沿用原有权限、模型和 API，执行后再次检查；其他已完成路径保留。

验收围绕当前节点的核心目标。一般不足、可选检查和改进建议写进报告，不阻止继续；核心交付缺失、必要条件未满足或缺少关键依据时才等待处理。

验收未通过时，可以：

- **返工并验收**：选择一个已执行的前序 Agent，补充修改要求。Agent 携带验收意见接续原任务，随后重新执行受影响的后续步骤。其他路径的结果保留；后续人工确认需要重新确认。
- **继续对话**：打开所选 Agent 的对话，进一步提问或修改产物。
- **重新验收**：产物已手动修改或通过对话更新后，读取最新文件再验收。

多个前序 Agent 汇合到同一验收节点时，也可以手动选择返工对象。返工前需等待其他执行节点结束；运行中可先「暂停派发」。人工确认不会自动通过。

### 上游输入

每个步骤接收已完成依赖的结果，包含来源步骤、执行次数、完成时间和相关文件正文。无关分支、未完成步骤和未选中的条件路径不参与交接。较长结果保留开头与末尾，避免丢失结论；结果和文件都有容量限制，截断与读取错误会单独标记。

在节点详情展开「上游输入」，可查看本次实际发送的内容，并打开来源任务。输入在派发前保存，后续文件修改不会改变旧记录；返工或重试会生成新一轮记录并读取最新文件。旧版本执行的步骤可能没有输入记录。

### 产物

点击任务右上角「详情」，在右侧面板切换到「产物」。左侧选择文件，右侧预览正文；查看产物时面板会加宽，窄屏时文件列表移到预览上方。文件较多时可搜索文件名。Markdown 支持切换源码，代码支持高亮和复制。点击「编辑」在文件标签页中修改，也可用系统程序打开。

列表收集 Agent 在最终回复「最终产物」段落中提交的文件，并核对文件是否存在，以及成功写入记录或执行期间的修改时间。只读取、未修改和已删除的文件不进入列表。旧记录没有产物段落时，仅显示各路径末尾已完成 Agent 引用的、有成功写入记录的文件。

自动读取范围为当前项目，以及用户目录中的 `.claude/plans`、`.codex/plans`、`.qwen/plans`、`.gemini/plans`。不会扫描整个目录；只收集当前运行引用的文件，拒绝目录穿越、文件符号链接和常见凭据文件。

每次最多收集 32 个文件。验收时单个文件最多读取 48 KB，正文总量最多 192 KB；Agent 交接正文总量最多 16 KB。最终产物优先收集，正文容量在已收集文件间分配，避免单个长文件占满容量。文件缺失、超出范围、格式不支持或被截断时会明确标记，不会声称已检查未读取的内容。面板展示磁盘上的当前文件，修改后可刷新。二进制文档暂不解析正文。

### 查看、暂停与恢复

启动后进入任务标签中的「工作流」视图。未开始节点使用中性虚线，运行中显示蓝色转动图标，已完成显示绿色对勾；等待确认、需要处理和跳过分别标注。进入运行节点的有效连线带流动效果，未选中的条件分支保持灰色虚线。系统开启「减少动态效果」时停用动画。

Agent 等待审批或回答问题时，运行页面显示「处理请求」。打开子任务处理后，工作流会在该任务完成后自动继续，不必重新启动。

画布左侧展示执行进度，右侧集中显示所选步骤的结果和操作。点击节点或通过「查看步骤」切换；点击 Agent 记录打开对应子任务。任务说明和之前的执行记录默认收起。确认、继续和返工按钮固定在步骤详情下方，只操作当前选中的步骤。切换查看节点不会改变执行状态。

- **暂停派发**：不再启动新节点，正在运行的节点结束后暂停。
- **继续执行**：调度尚未完成的节点，保留已有结果。
- **继续当前步骤**：继续失败或中断的 Agent 节点。优先恢复原会话；无法使用原会话的 Agent 会携带已有对话和执行记录继续。
- **重新执行**：从新的 Agent 会话执行该节点，保留其他节点的结果和已有文件修改。若子任务已手动完成，则直接使用其结果。
- **停止**：停止派发并取消正在执行的子任务，保留执行记录。
- **从断点继续**：恢复已停止的工作流。已完成和已跳过的节点保持不变，中断的 Agent 节点接着处理剩余工作，未完成的人工确认仍需审批。

继续会话不等于恢复进程中的某一条命令。Agent 会根据已有记录核对工作进度；原会话记录丢失导致恢复失败时，可选择「重新执行」。

LLM 检查和条件判断遇到连接失败、限流或服务暂时不可用时，分别等待 2 秒、4 秒，最多自动重试两次。重试进度显示在节点结果中；仍失败时保留原因，修正配置后可重试该节点。凭据错误、无效判断和检查不通过不会自动重试，也不会跳过人工确认。

多个节点需要处理时，通过画布或「查看步骤」选择；顶部「待处理」可定位到需要操作的节点，不必按列表顺序操作。确认或重试不要求其他独立 Agent 先结束。

运行状态和计划快照保存在本机。退出应用会停止正在执行的进程。重启后保留已完成的结果，不会自动派发；选中中断的 Agent 节点，点击「继续当前步骤」即可接续。修改库中的定义不会改变已有运行。旧版线性工作流打开编辑时会转换为顺序连线，保留逐步设置的 Agent；旧运行记录也支持继续。

每个工作流支持 1–24 个节点，每个节点最多执行 10 次，包含继续、重新执行和返工。Agent 默认不限时，可在高级设置中选填分钟数。工作流目前在本机执行，不提供定时触发或跨设备节点。

生成计划会将目标和可用 Agent 信息发送到配置的 LLM API；LLM 检查和条件判断还会发送节点说明、前序结果和引用文件的正文节选。Agent 使用各自的登录或所选 API。用量显示已上报的 Token，不估算未上报部分；计划生成的用量不计入后续运行。

## 归档和删除

工作流列表的归档按钮隐藏已不用的配置。点击 **已归档** 可恢复或删除。删除配置不会删除已有运行记录。

在 **运行记录** 中，结束的工作流可以归档。进入 **已归档** 后，勾选记录可批量恢复或删除。删除时默认保留项目文件和 Agent 原始历史；需要一并删除时，在确认框中关闭对应开关。

信息传递设计参考 [LangGraph 的状态与汇合](https://docs.langchain.com/oss/python/langgraph/workflows-agents) 和 [CrewAI 的任务依赖](https://docs.crewai.com/en/concepts/tasks)。
