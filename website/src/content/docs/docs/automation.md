## 任务模板

在新建任务输入框旁打开「任务模板」。模板可以分类、搜索、预览、编辑，也可以将当前输入保存为新模板。

模板中的 `{{变量名}}` 会生成填写项。例如：

```text
检查 {{模块}} 的错误处理，重点关注 {{场景}}。
先说明发现的问题，再修改代码并运行相关测试。
```

插入时默认追加到已有内容，选择替换才会覆盖。模板保存在本机的 `task-templates.json`。

## Prompt 优化

点击输入框旁的魔法棒，选择更清晰、更精简或结构化。此功能需要先配置 [LLM API](../api/)。

只发送当前输入文本，不读取项目文件、不启动 Agent。建议可以继续编辑，确认后替换原文，紧接着可以撤销。等待期间修改了原文，需要重新优化。

## 工作流

从左侧「自动化」进入，工作流与运行记录分开显示。工作流可以保存、复制和重复运行，删除工作流不会删除已有运行记录。

### 创建与启动

1. 点击「新建工作流」，也可以选择「分析 → 确认 → 实现 → 检查」等示例。
2. 填写名称、任务目标与项目目录。目录留空时，启动会创建临时项目。
3. 添加步骤，调整顺序，在右侧编辑每一步的内容。
4. 点击「保存工作流」以便复用；点击「启动」按当前编辑内容创建一次独立运行。

已有目标时，可以用「生成计划」生成步骤，需要先配置 [LLM API](../api/)。生成时只发送目标与可用 Agent 名称、标识和类型，不会读取项目文件。返回 2–12 个步骤，可继续修改内容、顺序、Agent 和权限，点击启动才会执行。生成的计划默认使用本机模型与 API 配置，不开启自动返工。仅由 Agent 任务和人工确认组成的工作流不需要额外配置 LLM。

### 步骤类型

| 类型 | 配置与行为 |
| --- | --- |
| Agent 任务 | 选择已安装的内置 Agent、只读或项目可写权限，填写具体工作。高级设置支持模型、Claude Code API 配置和执行限时。 |
| 人工确认 | 填写需要确认的事项。执行到此处暂停，可以补充要求后确认，也可以拒绝并停止。 |
| LLM 检查 | 填写验收标准，用配置的 LLM 对照前序结果检查。模型不会读取项目文件或执行测试，相关证据应由前面的 Agent 步骤提供。 |

步骤按顺序执行，共用一个项目。后一步收到任务目标、前序结果摘要和用户补充；因此可以让不同 Agent 接力分析、修改与验证。完整执行记录保留在对应子任务中，摘要有长度上限。

### 检查与返工

LLM 检查默认在不通过时暂停。如果紧接着 Agent 步骤，可以选择自动让该 Agent 返工，最多 1 次或 2 次。返工会收到检查意见，使用原有权限、模型和 API；返工后重新检查。

达到次数上限后等待用户处理。可补充说明后「返工上一步」或「重新检查」，也可以停止。人工确认不会因为等待时间过长而自动通过。

### 查看、暂停与恢复

启动后进入任务标签中的「工作流」视图，查看每一步的状态、结果、尝试次数和执行记录。需要完整对话时点击子任务的「执行记录」；父任务也有「对话」视图。

- **暂停派发**：让当前步骤结束后暂停，不启动下一步。
- **继续执行**：从未完成处继续，保留已经完成的步骤。
- **重试当前步骤**：再次执行失败或中断的步骤。已有文件修改不会撤销，重试前可查看子任务记录。
- **停止**：停止当前子任务并结束本次工作流。

运行状态、计划快照与结果保存在本机。重启后不会自动派发；已确认完成的步骤保留，未确认完成的执行需要手动处理。修改库中的工作流不会改变已有运行的计划。

每个工作流支持 1–24 步，Agent 步骤限时 1–120 分钟，默认 30 分钟；每步最多执行 10 次，包含重试与返工。工作流目前在本机执行，不提供定时触发、任意条件分支或同项目并行写入。

生成计划和 LLM 检查会将目标、步骤说明及所需结果发送到配置的 LLM API；Agent 使用各自的登录或所选 API 配置。工作流用量显示模型已上报的 Token，不估算未上报部分。计划生成的用量不计入后续运行。
